## 2. Âmbito
Homologar a prova de conceito que consulta um JSON num repositório GitHub privado, valida-o com o JSON Schema da fonte e apresenta dados e proveniência no frontend.

Esta aprovação é limitada ao caso de referência no laboratório. Não equivale a homologação de produção, ingestão em lote, persistência, sincronização ou processamento de anexos.

## 3. Evidências observadas

### 3.1 Autorização
Foi configurado um Fine-grained Personal Access Token com:
- Resource owner: carlos-andrade;
- Repository access: Only select repositories;
- Repositório selecionado: LICITACAO;
- Contents: Read-only;
- Metadata: Read-only (obrigatório).

O token é fornecido ao backend por variável de ambiente.

### 3.2 Acesso à fonte
Pedidos realizados de dentro do contentor backend à GitHub API devolveram:
- Repositório carlos-andrade/LICITACAO: HTTP 200;
- ARQUITETURA/exemplos/ufrj-2026-548-oportunidade.json: HTTP 200;
- ARQUITETURA/schemas/oportunidade.schema.json: HTTP 200.

### 3.3 Backend e endpoint
Os logs do contentor sistema-web-v1-backend mostram o Uvicorn iniciado em 0.0.0.0:8000, healthchecks de /api/health com HTTP 200 e pedidos ao endpoint /api/integrations/licitation/opportunities/reference originados pela rede Docker com HTTP 200.

Um teste no host contra 127.0.0.1:8000 falhou porque não havia serviço publicado nesse endereço loopback. Isso não contradiz as respostas HTTP 200 observadas entre frontend e backend na rede Docker. O acesso do host deve usar o endereço/interface publicado no Compose.

### 3.4 Frontend

A interface informa que schema válido não confirma exatidão factual, atualidade ou viabilidade.

## 5. Interpretação do registo

O resultado valid refere-se à conformidade estrutural do JSON com o schema. O valor has_conflicts é um estado de validação de conteúdo declarado no registo e não deve ser substituído por uma conclusão de validade material.

O registo contém datas de outubro de 2026, anteriores à data desta homologação (1 de novembro de 2026). É um caso de teste técnico, não uma oportunidade confirmada como aberta ou acionável.

O valor estimado é apresentado como recebido da fonte; esta homologação não verificou a sua exatidão comercial ou jurídica.

## 6. Limitações e testes não executados
- Não foi homologada consulta de múltiplas oportunidades.
- Não existe catálogo, pesquisa ou filtragem funcional.
- Não existe persistência local, histórico de snapshots ou deteção temporal de alterações.
- Não foram testados anexos PDF, CSV ou XLSX.
- Não foi testada sincronização agendada, webhook ou recuperação após indisponibilidade prolongada da GitHub API.
- Não foi realizada auditoria independente dos registos de atividade do GitHub para provar ausência absoluta de escrita.
- Não foi concluído teste de segurança de produção, gestão de utilizadores ou controlo de acesso à interface.
- O teste do host em 127.0.0.1:8000 não valida a publicação da porta quando o Compose a vincula a outro endereço.

## 7. Decisão

**APROVADO PARA A PROVA DE CONCEITO V1.2, COM ÂMBITO LIMITADO.**

A integração de referência está funcionalmente demonstrada entre GitHub, backend FastAPI e frontend React no ambiente de laboratório.

Esta aprovação não equivale a homologação de produção nem autoriza merge em main. A branch de trabalho permanece v1.2/licitacao-readonly.
