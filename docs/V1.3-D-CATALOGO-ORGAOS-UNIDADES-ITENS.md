# V1.3-D — Catálogo de órgãos compradores, unidades e itens

**Branch:** `v1.3-d/catalogo-compradores-itens`  
**Fonte de pesquisa:** `carlos-andrade/LICITACAO`, branch `main`, leitura exclusiva.  
**Destino de código e documentação:** `carlos-andrade/SISTEMA-WEB`.

## Escopo

Fluxo hierárquico: órgão comprador → unidade compradora → contratações identificadas no snapshot → itens efetivamente devolvidos pela API pública do PNCP. O objeto textual da contratação nunca é utilizado para fabricar ou inferir itens.

## Evidência da fonte

A captura `EDITAIS/pncp-editais-abertos.json` e os metadados foram consultados em `LICITACAO/main`. A captura indica:
- instante: `2026-10-30T15:08:35+00:00`;
- modalidade 8 (Dispensa);
- 34 registos únicos;
- uma página consultada;
- status `COMPLETO`.

**COMPLETO descreve a execução daquela captura**, não cobertura nacional nem o histórico integral de compras de qualquer órgão. A cobertura do catálogo é `PARTIAL`.

O snapshot contém os campos brutos `orgaoEntidade` e `unidadeOrgao`, incluindo CNPJ, razão social, código e nome da unidade, UF, município e código IBGE.

## Consulta de itens

A captura de contratação existente na fonte documenta a rota:

`https://pncp.gov.br/api/pncp/v1/orgaos/{cnpj}/compras/{ano}/{sequencial}/itens`

A rota é consultada sob demanda, com paginação de 100 itens por página e limite defensivo de 100 páginas. A API fornece número, descrição, material/serviço, quantidade, unidade, valores estimados, sigilo, situação, critério, benefício, código de catálogo e NCM/NBS.

Exemplo de evidência arquivada: contratação `00394502000144/2026/14259`, com 14 itens em `EDITAIS/CONTRATACAO-00394502000144-2026-14259/itens.json`. Esse exemplo não é atribuído automaticamente ao snapshot dos 34 registos.

## Endpoints

- `GET /api/licitation/buyers?q=&uf=&municipio=&page=1&page_size=20`
- `GET /api/licitation/buyers/{cnpj}/units/{unit_code}/contracts`
- `GET /api/licitation/contracts/{cnpj}/{year}/{sequence}/items`

O backend é o único componente que consulta GitHub e PNCP. Tokens não são enviados ao frontend.

## Integridade e limites

- LICITACAO permanece read-only.
- Hashes Git blob e SHA-256 dos bytes originais são apresentados como proveniência.
- CNPJs são validados quanto a formato e dígitos verificadores; inválidos são sinalizados, não eliminados silenciosamente.
- Compradores sem unidade identificável permanecem na pesquisa geral; filtros por UF/município exigem unidade correspondente.
- A consulta de itens é por contratação; não se deduzem itens a partir do objeto.
- Ausência de itens ou falha da API não prova que a contratação não tenha itens.
- Não existe persistência histórica nem agregação fora do snapshot.
- Orçamento sigiloso e valores nulos são preservados.
