### 3.4 Links de origem

No campo bruto `linkSistemaOrigem`:
- 20 registos têm valor nulo, vazio ou composto apenas por espaços;
- 14 têm conteúdo não vazio após trim;
- desses 14, 7 são URLs HTTP(S) absolutas;
- 6 não têm esquema HTTP(S);
- 1 contém apenas espaços.

Não corrigir o campo de origem in-place. O modelo do catálogo deve preservar o valor original e, se necessário, criar um campo derivado de URL normalizada, com proveniência explícita. Não abrir nem sondar os links durante esta validação.

### 3.5 Datas e fuso horário

As datas de negócio fornecidas sem offset são interpretadas como hora local de `America/Sao_Paulo`. O timestamp de captura é UTC e é convertido para esse fuso antes da comparação.

Com essa regra:
- nenhuma proposta tinha encerramento anterior à abertura;
- nenhuma publicação era posterior ao encerramento;
- nenhuma atualização era anterior à publicação;
- nenhum dos 34 registos tinha encerrado no instante da captura.

Esta conclusão depende da interpretação de datas sem offset como horário de Brasília. Se o contrato oficial do endpoint especificar outro fuso, a regra deve ser atualizada e o relatório reexecutado.

## 5. Implementação reproduzível

Script adicionado nesta branch:

`scripts/validate_pncp_semantics.py`

O script:
- consulta somente a API GitHub GET para obter os artefactos da branch `main` da fonte;
- reutiliza o leitor de blobs existente em `scripts/audit_licitacao_snapshot.py`;
- valida dígitos verificadores de CNPJ;
- valida formato do código IBGE e pertença da UF ao conjunto de siglas;
- cruza CNPJ, sequencial e ano do identificador PNCP com os campos do registo;
- valida datas com interpretação explícita do fuso `America/Sao_Paulo`;
- verifica modalidade, valores, campos obrigatórios e sintaxe dos links;
- produz JSON com SHA-256, perfil, contagens e ocorrências por registo;
- não escreve no repositório LICITACAO.

### Execução no Ubuntu

Depois de atualizar a branch:

```bash
cd ~/SISTEMA-WEB
git pull --ff-only origin v1.3-c/validacao-semantica-pncp

python3 -m py_compile scripts/validate_pncp_semantics.py

read -rsp "GitHub token read-only LICITACAO: " GITHUB_TOKEN
echo
export GITHUB_TOKEN

python3 scripts/validate_pncp_semantics.py \
  > /tmp/licitacao-semantic-v1.3-c.json \
  2> /tmp/licitacao-semantic-v1.3-c.log
RESULT=$?

unset GITHUB_TOKEN

echo "EXIT=$RESULT"
cat /tmp/licitacao-semantic-v1.3-c.log
wc -c /tmp/licitacao-semantic-v1.3-c.json
cat /tmp/licitacao-semantic-v1.3-c.json
```

O token necessita apenas de `Contents: Read-only` e `Metadata: Read-only` em `LICITACAO`. Não o colocar no histórico, nos ficheiros ou no relatório.

## 7. Limitações e decisões em aberto

1. O código IBGE é validado por formato de sete dígitos; ainda não é cruzado com uma tabela oficial de municípios.
2. Os quatro valores zero precisam de confirmação nos documentos/itens PNCP.
3. Links são validados sintaticamente, não testados por HTTP.
4. A interpretação de timestamps sem offset como `America/Sao_Paulo` deve ser confirmada contra o contrato da API.
5. A análise é do snapshot capturado, não de disponibilidade atual nem do estado atual dos processos.
6. O script remoto foi criado, mas a execução e validação no Ubuntu permanecem pendentes até a evidência local ser recebida.
