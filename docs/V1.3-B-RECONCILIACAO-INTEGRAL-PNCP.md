# V1.3-B — Reconciliação integral dos artefactos PNCP

## Objetivo

Comparar os três artefactos publicados no snapshot `LICITACAO/main`:
- `EDITAIS/pncp-editais-abertos.csv`;
- `EDITAIS/pncp-editais-abertos.json`;
- `EDITAIS/pncp-editais-abertos.xlsx`.

O processo é exclusivamente read-only relativamente ao repositório LICITACAO. O script consulta a API GitHub, recupera blobs e produz um relatório JSON em stdout.

## Implementação

Script: `scripts/reconcile_pncp_artifacts.py`.

O script reutiliza o leitor ZIP/XML e os métodos de acesso GitHub definidos em `scripts/audit_licitacao_snapshot.py`. A transformação JSON bruto -> 26 colunas replica a função `flatten` do script de captura da fonte, sem importar nem executar código do repositório LICITACAO.

## Comparações

1. Contagem de registos nos três formatos.
2. Conjuntos de identificadores `numero_controle_pncp`.
3. Identificadores duplicados por formato.
4. Cabeçalhos e conjunto das 26 colunas esperadas.
5. Comparação por identificador e campo entre CSV, JSON achatado segundo o mapeamento da fonte e XLSX.
6. Contagem integral de divergências por campo e amostra de até 1.000 divergências detalhadas.
7. SHA-256 dos quatro artefactos recuperados.

A comparação é feita sobre os valores exportados como strings. Não se presume equivalência semântica além da transformação explicitamente replicada.

## Semântica conhecida

- `uf`: o mapeamento da fonte consulta `unidadeOrgao.uf` e depois `uf` na raiz; não consulta `unidadeOrgao.ufSigla`.
- `link_sistema_origem`: o mapeamento da fonte prefere `linkSistemaOrigem` e usa `linkProcessoEletronico` como fallback.
- `link_pncp`: URL derivado do número de controle, não campo bruto equivalente.
- `capturado_em_utc`: timestamp de metadados da captura, replicado em cada linha exportada.

Os campos derivados ou preenchidos por fallback devem ser distinguidos dos valores de origem no modelo canónico do SISTEMA-WEB.

## Execução no Ubuntu

Após atualizar a branch local:

```bash
cd ~/SISTEMA-WEB
git pull --ff-only origin v1.3/catalogo-oportunidades

read -rsp "GitHub token: " GITHUB_TOKEN
echo
export GITHUB_TOKEN

python3 scripts/reconcile_pncp_artifacts.py \
  > /tmp/licitacao-reconciliation-v1.3-b.json \
  2> /tmp/licitacao-reconciliation-v1.3-b.log
RESULT=$?

unset GITHUB_TOKEN

echo "EXIT=$RESULT"
cat /tmp/licitacao-reconciliation-v1.3-b.log
wc -c /tmp/licitacao-reconciliation-v1.3-b.json
cat /tmp/licitacao-reconciliation-v1.3-b.json
```

O token necessita de acesso `Contents: Read-only` e `Metadata: Read-only` ao repositório LICITACAO. Não colocar o token no comando, no código, em ficheiros ou no relatório.

## Critérios de aceitação

- Execução termina com código 0.
- CSV, JSON achatado e XLSX têm 34 identificadores únicos e conjuntos idênticos.
- Os cabeçalhos CSV/XLSX correspondem às 26 colunas esperadas.
- Todas as divergências estão quantificadas e localizadas por identificador/campo.
- Nenhuma divergência é corrigida silenciosamente.
- SHA-256 dos artefactos é registado no relatório.
- A origem LICITACAO não recebe qualquer escrita.

A aprovação da reconciliação não implica que os dados estejam semanticamente corretos ou atuais; apenas demonstra o grau de concordância entre as exportações segundo as regras de transformação documentadas.
