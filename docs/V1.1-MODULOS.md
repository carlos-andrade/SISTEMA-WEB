# SISTEMA WEB V1.1 — Navegação e módulos

## Objetivo

Evoluir o bootstrap V1 com navegação funcional para os seis módulos da aplicação, mantendo o frontend React/TypeScript, o backend FastAPI e a implantação Docker Compose existentes.

## Módulos incluídos

| Módulo | Implementação V1.1 | Limite atual |
|---|---|---|
| Visão geral | Dashboard e consulta manual do endpoint de saúde | Não é uma consola de monitorização completa |
| Infraestrutura | Inventário inicial de recursos e estados conhecidos | Sem recolha dinâmica do Ubuntu |
| Integrações | Catálogo de integrações previstas | Sem conectores externos ativos |
| Dados | Estado da API, persistência e rastreabilidade | PostgreSQL e histórico não implementados |
| Topologia | Ligações lógicas da arquitetura atual | Sem descoberta automática da rede |
| Segurança | Exposição conhecida, isolamento e controlos pendentes | Não constitui auditoria ou certificação |

## Regras de apresentação

- Não apresentar dados simulados como telemetria real.
- Distinguir estados implementados, validados, planeados e não integrados.
- As integrações com Zabbix, ChirpStack, Docker e Ubuntu começam em modo de consulta.
- Não alterar a configuração dos serviços existentes durante a fase de leitura.
- LICITACAO permanece exclusivamente como fonte de consulta. Não gravar nem alterar ficheiros nesse repositório.

## Alterações técnicas

- Navegação lateral controlada por estado React.
- Seis páginas funcionais no frontend.
- Consulta do endpoint `/api/health` no dashboard.
- Ação manual para atualizar o estado da API.
- Componentes de estado reutilizáveis.
- Layout responsivo para a navegação e páginas dos módulos.

## Validação no servidor

A validação local do código e a validação funcional no navegador são etapas obrigatórias. Após atualizar o clone:

```bash
cd "$HOME/SISTEMA-WEB"
git pull origin v1/bootstrap-dark-docker
sudo docker compose -f deploy/docker-compose.yml up -d --build
sudo docker compose -f deploy/docker-compose.yml ps
sudo docker compose -f deploy/docker-compose.yml logs --tail=80
```

Verificar o frontend e o proxy da API:

```bash
curl --fail http://192.168.60.141:5173/
curl --fail http://192.168.60.141:5173/api/health
curl --fail http://192.168.60.141:8000/api/health
```

## Roteiro de homologação manual

1. Abrir o dashboard em `http://192.168.60.141:5173`.
2. Clicar em cada um dos seis módulos da sidebar.
3. Confirmar que o título e o conteúdo correspondem ao módulo selecionado.
4. Na Visão geral, utilizar a ação de atualização da API.
5. Confirmar que os estados planeados/não integrados estão identificados.
6. Repetir a navegação numa janela estreita ou dispositivo móvel.
7. Verificar a consola do navegador quanto a erros JavaScript.
