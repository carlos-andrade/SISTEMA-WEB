## 4. Reconciliação CSV versus JSON

Foram comparados 24 campos correspondentes, com mapeamento explícito entre os nomes achatados do CSV e os campos do JSON, incluindo campos aninhados. A comparação normalizou diferenças de representação que não alteram o valor: espaços/quebras de linha, booleanos `Sim/Não` versus `true/false`, números como `28690.0` versus `28690`, e ausência representada por null ou string vazia.

Resultado:

- 22 dos 24 campos mapeados coincidem nos 34 registos.
- `uf`: divergência nos 34 registos — CSV vazio; JSON contém siglas como BA, GO e SP.
- `link_sistema_origem`: duas divergências — o CSV contém URLs de origem para dois registos, mas o JSON tem null.
- Nos restantes 22 campos mapeados, não foram detetadas diferenças após normalização.
- `link_pncp` e `capturado_em_utc` são campos derivados/da exportação CSV sem correspondência direta equivalente no objeto JSON bruto e não foram incluídos na comparação campo a campo.

As duas divergências de `link_sistema_origem` devem ser tratadas como enriquecimento na exportação CSV, não como prova de que o JSON está incompleto. A regra de fonte de verdade deve preservar o objeto JSON bruto e manter o valor CSV como campo derivado com proveniência própria, até a origem do enriquecimento ser confirmada.
